# Translations

How Modbench shows its interface in other languages (issues #91 and #92).

## Languages

| Locale | Language | Shown as |
|---|---|---|
| `en` | English: the source language and the fallback | English |
| `pt-PT` | Portuguese (Portugal) | Português (Portugal) |
| `ru` | Russian | Русский |
| `zh-Hans` | Chinese, simplified script | 简体中文 |

Locale identifiers are BCP 47 tags. `zh-Hans` names the script rather than a
country: it covers mainland China and Singapore alike.

## Choosing the language

- **First start:** the system's languages (`navigator.languages`, most
  preferred first) are matched against the table: any Portuguese gives
  `pt-PT`, Russian `ru`, Chinese in simplified script (`zh`, `zh-CN`,
  `zh-SG`, `zh-Hans`) `zh-Hans`. Traditional Chinese (`zh-TW`, `zh-HK`,
  `zh-Hant`) is not matched. The first match wins; with none, English.
- **Settings › Appearance › Language** lists "Same as system (…)" and the
  languages by their own names. An explicit choice is saved with the other
  settings and wins over the system's language on later starts. It applies at
  once, without a restart.
- Installers do not ask for a language.

## How strings are looked up

- Catalogues are JSON files in `src/lib/locales/`, one per locale, flat:
  `"key": "text"`. Keys are dotted by area: `nav.*`, `step.*`, `test.*`,
  `tab.*`, `tools.*`, `settings.*`.
- `t("key", { name: value })` in a component returns the text in the current
  language. `{name}` in a text is replaced by the value.
- Plurals: an entry can be an object of `Intl.PluralRules` forms (`zero`,
  `one`, `two`, `few`, `many`, `other`); `t("count.registers", { count: 5 })`
  picks the form for 5 in the current language (Russian needs `one`, `few`
  and `many`; Chinese only `other`).
- Missing in a language → the English text. Missing in English → the key
  itself, which the tests catch.
- `en.json` defines the keys: the TypeScript type of `t()` accepts only keys
  that exist in English.

The lookup is a small module (`src/lib/i18n.svelte.ts`, no dependency):
the strings are short labels, plurals are rare, and `Intl` is in every
webview Modbench runs on. If messages with selects or nested plurals become
common, the catalogues can move to the ICU MessageFormat syntax without
changing the keys.

## What is translated

Done first, to agree on the approach before translating everything:

- the top navigation, the three step titles and the test controls of the Main
  page, and the names of its tabs;
- the Tools list (section titles, tool names and hints);
- the Settings categories and the Appearance section, with the language
  selector.

The rest of the interface, error messages from the backend, the command line
and the manual stay in English for now; they move to catalogues page by page.
Device maps are never translated: register names come from the map file.

## Fonts and layout

Inter (the interface font) covers Latin and Cyrillic. Chinese falls back to
the system's CJK font (`PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`,
`Noto Sans CJK SC`). Russian and Portuguese labels are longer than English
ones (up to about 40 %), so labels must wrap or truncate with a title, never
overflow; check a new page with Russian.

## Adding or changing a translation

1. Copy `src/lib/locales/en.json` to `src/lib/locales/<locale>.json` (or edit
   the existing file) and translate the values. Keep `{placeholders}`
   exactly, and give every plural form the language uses.
2. Register a new locale in `src/lib/i18n.svelte.ts` (`Locale`, `CATALOGUES`,
   `LOCALES`, and `detectLocale` if its tags need mapping).
3. Run `npm test`: `i18n.test.ts` checks that every key exists in English,
   that placeholders match, that strings stay strings and plurals plurals, and
   that the shipped languages cover every English key.
4. Open a pull request. Translations from a native speaker are preferred; the
   first Russian and Chinese texts were written without one and are open to
   corrections.
