\chapter{The device library}
\label{ch:library}

The Library page keeps your device maps in one folder, and brings maps from
the shared online library.

   description, number of registers and status icons; the search field and the

\section{Your library}

The list shows each map's vendor (with its icon), model, description, number
of registers and status (Section~\ref{sec:map-status}). \field{Search vendor or
model} filters it.

Right-click a map:

\begin{description}[style=nextline, leftmargin=0pt, font=\intermedium]
  \item[Use] Opens it on the Main page.
  \item[Explore] Shows the registers of the map, with a search, and its
    properties, translation tables, no-data values and sources, without using
    it.
  \item[Edit…] Opens the map in the map builder (next section).
  \item[Open in a text editor…] Opens the file in your text editor, after
    asking.
  \item[Duplicate] Makes a copy of the map in the library.
  \item[Simulate this device] Opens the simulator with a device shaped after
    this map (Chapter~\ref{ch:simulator}).
  \item[Export for other software…] Writes the map as the Modbus
    configuration of Home Assistant, sensors for ESPHome, an input of
    Telegraf, a Node-RED flow (with node-red-contrib-modbus) or a CSV tag list
    for PLC and SCADA tools. The device's address comes from
    the connection of step 1, or is left as \val{<host>} to fill in. Registers
    a format cannot express are listed at the top of the file.
  \item[Copy name, Copy file path] For notes and other programs.
  \item[Open the library folder] Shows the folder in your file manager.
  \item[Delete…] Removes the map from the library, after asking.
\end{description}

Maps with errors are listed with the problem, so they can be fixed in a text
editor.

\section{Adding maps}

\begin{description}[style=nextline, leftmargin=0pt, font=\intermedium]
  \item[\ui{From a file…}] Copies \file{.mbmap.json} or \file{.mbmap} files into
    the library. Version 1 files are converted.
  \item[\ui{From the online library…}] Opens the shared library (below).
\end{description}

The library is a folder (\nav{Settings\then Device library\then Library
folder}): files copied into it by hand appear too.

\section{The map builder}
\label{sec:builder}

\ui{Map builder} (in the Library's toolbar) opens a window of its own, next to
the main one, to write a map without a text editor. \ui{Edit…} in a map's
right-click menu opens that map in it. \ui{New map} starts an empty one,
\ui{Open a map…} loads a file.

The window has the map's header and a table of its registers. It checks the
map with the same rules as a file while you type, and says so at the top:
\emph{No problems found}, or the number of errors and warnings, with the
cause beside each one. \emph{Unsaved changes} shows when the map differs from
what is on disk.

\begin{description}[style=nextline, leftmargin=0pt, font=\intermedium]
  \item[Device] Vendor, model and the other fields that name the device, the
    source it was made from (manual, version, URL) and the connection defaults
    that are filled in when the map is used.
  \item[Optional parameters] The firmware the map is for (\field{Firmware
    from} and \field{Firmware up to}), the date it was revised, the most
    registers or bits one read may ask for, the models it covers and notes,
    one per line. \ui{Sources} lists the documents the map was made from.
    Named state labels, the no-data values by type and any other keys of the
    file (the ones that begin with \val{x\_}) are here too.
  \item[Address base] How the manual numbers its addresses, from 0 or from 1.
    Addresses in the table are typed as the manual writes them.
  \item[Registers] One row for each register. \ui{Add a register} adds a row;
    each row can be moved up or down, duplicated or deleted, and
    \ui{Edit register…} opens all of its fields. State labels are written as
    pairs, such as \val{0=Off, 1=On}.
  \item[Changes from the original] Lists what was added, removed or changed
    since the map was opened.
\end{description}

\ui{Save as…} writes a version 2 \file{.mbmap.json}. A map that came from the
library is saved back to its file with \ui{Save}, or copied elsewhere with
\ui{Save as…}; errors must be fixed before it goes into the library, and
Modbench asks before it replaces a map the library already has for the same
vendor and model. \ui{Open in a text editor…} opens the file instead.

\subsection{Importing a register table}

Manuals list registers in tables. \ui{Import a table…}, in the map builder,
turns one into the registers of a map. Paste the table copied from a
spreadsheet or a manual (\val{Ctrl+V}), or open a CSV file.

Modbench reads the header to guess what each column holds (name, group, area,
address, type, length, scale, unit, access or description). Each guess can be
changed, a column can be left out, and \field{The first row is a header} is
ticked when the first row looks like one. Types, scales and access are read the
way manuals write them (\val{x0.1}, \val{1/10}, \val{R/W}), and so are
addresses such as \val{40001}. Rows that do not say
which area they belong to (coils, holding registers…) use
\field{Area of rows that name none}. Addresses are read the way the manual
numbers them, that is, with the map's address base.

A cell that could not be read keeps the default value and is marked in red,
and the message after the import names the rows to check.
\ui{Replace the registers} swaps the map's registers for the table;
\ui{Add to the map} keeps them and appends the rows.

\section{The online library}

\screenshot[7cm]{online-library}{Choosing a map in the online library.}
  {The online library: vendors on the left with their icons, the models of one
   vendor on the right, one map selected.}

The online library lists the maps shared on GitHub
(\web{github.com/nobrega8/mbmap-library}): over 400 maps of meters,
inverters, drives and controllers.

\begin{steps}
  \item Choose a vendor; \ui{Back to all vendors} (or \key{Esc}) goes back.
  \item \ui{Add} next to a model downloads its map into your library.
  \item \ui{Done} closes the online library.
\end{steps}

A map already in your library can be downloaded again, to replace your copy
with the newest one.

\begin{tip}[Share your maps]
A map that works with a real device helps the next person with the same
device. The library's repository explains how to contribute one, and the
format specification is linked from \nav{Settings\then Device library}.
\end{tip}

\section{Finding the map for a device}
\label{sec:find-map}

\ui{Find} under \ui{Find a map for this device} checks the maps of the library,
and the maps open on the Main page, against the device of step 1 (it connects
for the check if needed, and only reads). Many maps declare identity
registers: the device's model, its firmware version, or registers with a known
reference value. Each distinct identity register is read once, however many
maps declare it, and each map is compared with what the device answered:

\begin{itemize}
  \item a model register must name one of the map's models;
  \item every reference value must match;
  \item a firmware outside the map's range is shown as a warning, not ruled out.
\end{itemize}

The maps that fit are listed best first, with what matched (\val{model EM540},
\val{2 references}, \val{firmware 2.1}); \ui{Open} opens one. Maps without
identity registers cannot be checked and are not listed.

The simulator, shaped after a map, answers its model register with the map's
first model, so a map can be tried out with this search too.
